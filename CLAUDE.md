# Kilocode AI Development Guidelines

## Системные команды (Build & Test Commands)
* Сборка приложения: `make build` или `go build ./cmd/...`
* Запуск всех тестов: `make test` или `go test -v -race ./...`
* Запуск линтера: `make lint` или `$(shell go env GOPATH)/bin/golangci-lint run`

## Строгие правила кодинга для Go 1.26 (Strict Coding Guidelines)
1. **Формат HTTP-ответов**: Полный запрет на plain-text ответы через `http.Error`. Любая ошибка должна возвращаться строго в формате JSON: `{"error": "сообщение"}` со статусом 4xx/5xx.
2. **Обработка и маппинг ошибок**: Запрещено использовать хрупкий паттерн `strings.Contains(err.Error(), "...")`. Все доменные ошибки должны быть типизированы в слое Domain (пакет `internal/pkg/apperror`). В хендлерах проверку делать строго через `errors.Is(err, ...)` и маппить на соответствующие HTTP-коды.
3. **Безопасность (API Key)**: Все эндпоинты, кроме `/healthz`, должны быть защищены Middleware аутентификации, проверяющей заголовок `X-API-Key`.
4. **Валидация файлов**: Проверка загружаемых медиафайлов должна осуществляться по реальному содержимому (Magic Bytes) через `http.DetectContentType`.
5. **Фоновые процессы**: Команды `ffmpeg` должны запускаться строго с использованием `exec.CommandContext` для предотвращения утечек ресурсов.
